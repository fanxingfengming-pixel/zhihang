# 职航 Agent Prompt 评测

## 目标与边界

- Prompt 版本：`2026-09-07.1`
- 部署模型：DeepSeek 与 Qwen，共用同一份提供商无关基础 Prompt。
- 当前自动评测对象：本地演示引擎、Zod 输出契约、事实边界和关键业务不变量。
- 当前不自动调用付费 API；真实模型语义质量、延迟和成本需在显式设置密钥并授权费用后另行评测。

## 数据集

评测集位于 `tests/fixtures/agent-evals.ts`，覆盖全部 10 个 Agent。每个 Agent 至少有：

1. 一条 `baseline`：代表正常、信息相对完整的任务。
2. 一条 `holdout`：代表稀疏输入、缺失信息或不能过度推断的任务。

总计 20 条固定案例。保留集不应为了通过单次修改而单独打补丁；同一根因应在公共约束、输出契约或后处理守卫中修复。

## 自动评分标准

每条案例同时检查：

- 输出能通过对应 Zod Schema。
- 必要事实、状态或记录 ID 被保留。
- 禁止的虚构事实或外部执行声明不出现。
- 数组数量、四周计划、面试题数等关键业务不变量稳定。
- 模型结果经过 `secureAgentResult` 后仍满足相同契约。

运行：

```powershell
Set-Location "D:\CodexProjects\明途科技"
pnpm test:evals
```

## 基线结果

`2026-09-07.1` 在本地确定性评测中通过 20/20 案例，公共 Prompt 契约通过 10/10 Agent。该结果证明结构和关键不变量可重复，不等同于 DeepSeek/Qwen 的真人质量评分。

## 后续真实模型评测

连接真实 API 后，在同一批案例上分别记录 DeepSeek 与 Qwen 的：

- 指令遵循、输出结构、事实忠实度、歧义处理。
- API 延迟、失败率和单次成本。
- 原始模型输出、守卫后的输出与失败原因。

只有当同一修改同时通过 baseline、holdout 和原始失败回放时，才升级 `PROMPT_VERSION`。若分数停滞或仅对单条案例改善，应停止继续堆叠 Prompt。
